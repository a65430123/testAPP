# 客服流程

這份文件給客服與 GM 使用：有哪些管道、案件怎麼分級、常見案件一步一步怎麼處理、哪些事不能做。

所有查詢與處置都在管理後台（`/admin.html`）進行。後台功能說明見 `README.md` 的「管理後台」一節。

## 1. 需要你決定的事

| # | 決定 | 建議 |
|---|---|---|
| 1 | 客服管道 | **客服信箱 + 官網表單**為正式管道（有紀錄）；Discord 或 LINE 官方帳號做即時公告與一般問答，但不在上面處理帳號與金流問題 |
| 2 | 服務時間 | 開服初期每日 10:00–22:00（台北時間），其餘時間只處理 P1 |
| 3 | 道具遺失的補償原則 | **有紀錄佐證才補**；`item_log` 查得到是伺服器問題就原物補回，查不到就不補 |
| 4 | 帳號被盜的處理 | 協助取回帳號；被轉走的道具**原則上不從第三方追回**，除非能證明收受方是同一人 |
| 5 | 案件系統 | 初期用共用信箱加試算表即可；每日案件超過 30 件再導入工單系統 |

## 2. 管道

| 管道 | 用途 | 回覆時限 |
|---|---|---|
| 客服信箱【support@你的網域】 | 所有正式案件：帳號、儲值、檢舉、申訴、個資請求 | 依第 3 節分級 |
| 官網回報表單 | 同上；表單強制填帳號、角色名稱、發生時間、問題類別，可省下來回詢問 | 同上 |
| 遊戲內檢舉（規劃中） | 檢舉外掛、騷擾、不當名稱；自動帶入雙方角色與時間 | 3 個工作天內處理，不逐案回覆 |
| Discord／LINE 官方帳號 | 公告、維護通知、一般玩法問答 | 盡力而為 |
| 管理後台的全伺服器公告 | 維護預告、緊急通知 | — |

**身分確認**：凡是涉及帳號歸屬、儲值、退款、個資的案件，一律要從**帳號註冊或儲值時留下的聯絡方式**來信，或提供儲值紀錄（金額、時間、付款方式末幾碼）佐證。不接受只憑帳號名稱就處理。

> 目前註冊只有帳號與密碼，沒有 Email。開服前要補上「綁定 Email」，否則帳號被盜與忘記密碼都無法確認身分。這一項已列入開服檢查清單。

## 3. 案件分級與時限

| 等級 | 定義 | 範例 | 首次回覆 | 解決目標 |
|---|---|---|---|---|
| P1 緊急 | 影響多數玩家，或正在造成金錢損失 | 伺服器連不上、儲值普遍不到帳、道具複製漏洞、大規模盜帳 | 30 分鐘內（含非服務時間） | 持續處理到解決，每小時更新公告 |
| P2 高 | 單一玩家的金錢或帳號問題 | 儲值未到帳、帳號被盜、誤封申訴、未成年退款 | 4 小時內（服務時間） | 2 個工作天 |
| P3 一般 | 遊戲內問題，不涉及金錢 | 道具遺失、卡在地圖、任務無法完成、檢舉 | 1 個工作天 | 5 個工作天 |
| P4 低 | 建議與一般詢問 | 玩法問題、功能建議 | 3 個工作天 | — |

P1 的通報對象：值班工程師與營運負責人。伺服器的警示 Webhook（外掛踢除、經濟異常、伺服器錯誤）也會發到同一個頻道。

## 4. 處理原則

1. **先查紀錄，再回覆。** 道具查 `item_log`（後台角色頁有最近 50 筆；需要更早的請工程師查資料庫），安全事件查「安全事件」分頁，GM 做過什麼查「操作紀錄」。
2. **所有處置都要留原因。** 後台的封鎖與發放都強制填寫原因，請寫清楚案件編號與依據，例如「案件 #1234：伺服器回溯造成道具遺失，依 item_log 補回」。
3. **不向玩家索取密碼。** 任何情況都不需要。
4. **不透露其他玩家的資料**，包括帳號、IP、儲值情形、被檢舉後的處分內容。對檢舉人只回覆「已收到並依規定處理」。
5. **GM 不得用後台圖利自己或他人。** 所有發放都在 `admin_log` 與 `item_log` 留下紀錄，每週由另一位管理員抽查。
6. **拿不準就升級**，不要自行判斷後處置（見第 7 節）。

## 5. 常見案件處理步驟

### 5.1 儲值未到帳（P2）

> 商城與金流上線後適用。

1. 請玩家提供：帳號、儲值時間、金額、付款方式、金流的交易編號或繳費收據。
2. 後台查訂單：
   - 訂單「已付款」但玩家說沒收到 → 請玩家重新登入確認餘額；查星鑽異動紀錄確認已入帳。
   - 訂單「待付款」→ 到金流後台查同一筆交易。金流顯示已收款：由管理員補單。金流顯示未收款：告知玩家款項尚未完成（ATM 與超商可能有入帳時間差，請對方保留收據）。
   - 查不到訂單 → 確認玩家是否儲值到別的帳號或別的遊戲。
3. 補單後回覆玩家，並在案件上記錄補單的操作紀錄編號。
4. 同一時段出現 3 件以上 → 升級為 P1，通知工程師檢查金流通知是否異常。

### 5.2 帳號被盜（P2）

1. 確認身分（第 2 節）。
2. 後台**先封鎖帳號**（原因寫「疑似被盜，保護性封鎖，案件 #…」），防止繼續損失。
3. 查該帳號角色的 `item_log`，看異常時段的 `trade_out`、`shop_sell`、`storage_out`。
4. 協助重設密碼（需要工程師協助，目前後台沒有重設密碼功能），解除封鎖。
5. 被轉走的道具：依決定事項第 4 點處理。若收受方帳號明顯是盜帳者（例如只收不玩、短時間收受多個被盜帳號的道具），封鎖收受方並回報營運負責人決定是否追回。
6. 提醒玩家：不要與他人共用帳號、不要在其他網站用相同密碼。

### 5.3 道具遺失或數量不對（P3）

1. 請玩家提供：角色名稱、道具名稱、大約的發生時間、最後一次看到道具時在做什麼。
2. 後台角色頁查「最近 50 筆道具異動」，找那個道具：
   - 有 `shop_sell`、`trade_out`、`use`、`refine`、`card_insert`、`quest_turn_in` → 是玩家自己的操作，向玩家說明時間與操作，不補償。
   - 有 `storage_in` → 道具在倉庫，請玩家去找倉庫管理員。
   - 完全沒有對應的減少紀錄，但現在確實不在 → **升級給工程師**。這代表可能有程式問題，不要先補。
3. 確認是伺服器問題後，由管理員用後台發放補回，原因寫明案件編號。

裝備可以用**道具編號**追蹤完整歷程（買入、精煉、交易給誰）。後台角色頁的裝備與背包清單有顯示編號。

### 5.4 精煉失敗、機率相關申訴（P3）

1. 查 `item_log` 的 `refine` 紀錄，`detail` 欄有精煉前後的等級與是否成功。
2. 向玩家說明成功率（遊戲內精煉視窗有顯示）與紀錄上的結果。精煉失敗不是錯誤，不補償。
3. 同一位玩家連續失敗次數明顯異常（例如 80% 成功率連續失敗 10 次以上）→ 把紀錄轉給工程師確認亂數是否正常。

### 5.5 檢舉外掛（P3）

1. 後台「安全事件」分頁查被檢舉角色有沒有 `cheat_warn`、`cheat_kick`、`coin_rate`。
2. 角色頁看等級、星幣、最近的道具異動是否合理（例如新角色短時間大量 `shop_sell` 同一種素材）。
3. 處置建議：

| 情況 | 處置 |
|---|---|
| 只有檢舉、沒有任何紀錄佐證 | 不處分，列入觀察 |
| 有 `cheat_warn` 但沒有其他異常 | 不處分，列入觀察；可能是網路不穩或連點 |
| 多次 `cheat_kick` | 封鎖 3–7 天，原因寫明事件 |
| `cheat_kick` 加上經濟異常，或有明確的自動化證據 | 封鎖 30 天至永久；回報營運負責人 |

4. 封鎖原因玩家登入時會看到，請寫得具體且有禮貌，例如「偵測到多次異常操作（2027/01/05），暫停使用 7 天。如有疑問請來信客服」。
5. 遊戲**允許掛機打怪**（GDD 的設計），不要因為「長時間在線」就處分。

### 5.6 封鎖申訴（P2）

1. 由**不是原本做出封鎖決定的人**複查：操作紀錄裡的原因、對應的安全事件、角色的道具異動。
2. 證據不足 → 解除封鎖並致歉。證據充分 → 維持，回覆中說明依據的事件類型與時間（不透露偵測門檻等細節）。
3. 永久封鎖的申訴一律由營運負責人做最後決定。

### 5.7 未成年人儲值退款（P2）

1. 請法定代理人來信，提供：玩家帳號、儲值紀錄、法定代理人與未成年人的關係證明、雙方的身分證明（可遮蔽不必要的欄位）。
2. 查核後封鎖帳號的儲值功能，計算可退金額（原則見 `MONETIZATION.md` 第 6 節）。
3. 走原付款管道退款，後台登記，收回星鑽與已購買的權益。
4. 把該帳號標記為未成年，套用較低的儲值上限。
5. 收到的身分證明文件只用於本案，結案後依隱私權政策的保存期限刪除。

### 5.8 騷擾、不當名稱（P3）

1. 請檢舉人提供截圖與時間。目前聊天內容**沒有存進資料庫**，無法事後調閱；這一點已列入開服檢查清單。
2. 不當角色名稱或公會名稱：通知玩家限期改名，逾期由管理員處理（改名功能尚未實作，需工程師協助）。
3. 騷擾屬實：依情節禁言或封鎖（禁言功能尚未實作，目前只能封鎖）。

### 5.9 個資請求（P2）

玩家依個人資料保護法請求查詢、更正、停止利用或刪除個資：

1. 確認身分。
2. 轉給個資負責人，於法定期限內回覆（查詢與提供複本原則上 15 日內、更正與刪除 30 日內，可依法延長；請以現行法規為準）。
3. 刪除帳號：金流與發票紀錄依稅法需保存的部分不能刪，回覆時要說明。

## 6. 回覆範本

依情況調整，不要原封不動貼上。

**收到案件**
> 您好，我們已收到您的來信（案件編號 #____）。為了協助您，請補充以下資訊：帳號名稱、角色名稱、問題發生的大約時間。我們會在 ____ 內回覆您。

**查無異常（道具）**
> 您好，我們查詢了角色「____」的道具紀錄。紀錄顯示該道具於 ____ 透過「____」（例如：賣給商店）離開背包，屬於正常的遊戲操作，因此無法補發。若您認為紀錄有誤，請告訴我們當時的操作情形，我們會再確認。

**確認為系統問題並補償**
> 您好，經確認這是系統問題造成的，造成您的不便非常抱歉。我們已將「____ ×__」補發至角色「____」的背包，請登入確認。

**封鎖通知的回覆**
> 您好，帳號「____」因 ____（日期）偵測到多次異常操作，依服務條款第 __ 條暫停使用 __ 天，將於 ____ 自動恢復。若您認為有誤，請回覆本信說明，我們會由另一位同仁重新檢視。

**維護公告**
> 【維護公告】伺服器將於 __ 月 __ 日 __:__–__:__ 進行維護，期間無法登入。維護內容：____。造成不便敬請見諒。

## 7. 升級

| 情況 | 升級給 |
|---|---|
| 紀錄與實際狀況對不上（道具憑空消失或多出來） | 工程師，並視為可能的 P1 |
| 同一問題短時間多人回報 | 值班工程師 + 營運負責人 |
| 需要後台沒有的操作（重設密碼、改名、查更早的紀錄、聊天調閱） | 工程師 |
| 永久封鎖、追回道具、金額超過【門檻】的退款 | 營運負責人 |
| 玩家表示要向消保官申訴、提告，或媒體詢問 | 營運負責人，不自行回覆 |
| 涉及人身安全（自傷、威脅他人、兒少安全） | 立即通報營運負責人；必要時聯繫警方 |

## 8. 目前後台做不到、客服會需要的功能

這些要在開服前補齊或有替代流程（已列入開服檢查清單）：

| 需求 | 現況 | 替代做法 |
|---|---|---|
| 重設密碼、綁定 Email | 沒有 | 工程師直接處理；開服前必須實作 |
| 禁言 | 沒有 | 只能封鎖 |
| 改角色名稱、公會名稱 | 沒有 | 工程師直接改資料庫 |
| 把卡住的角色移回城 | 沒有 | 角色倒地後會自動回城；或工程師改資料庫 |
| 聊天紀錄調閱 | 聊天沒有存檔 | 請玩家提供截圖 |
| 查超過 50 筆的道具紀錄、依道具編號查 | 後台只顯示最近 50 筆 | 工程師用 `README.md` 裡的 SQL 查詢 |
| 訂單查詢、補單、退款登記 | 商城尚未實作 | — |
| 案件紀錄 | 沒有 | 共用信箱 + 試算表 |

## 9. 每日與每週例行工作

**每日**

- 檢查後台「安全事件」中的警示等級事件，逐筆處理或註記。
- 檢查未結案件是否超過時限。
- （金流上線後）確認前一日的對帳結果。

**每週**

- 由另一位管理員抽查「操作紀錄」中的發放與封鎖是否都有合理原因。
- 整理本週前五大問題類型，回饋給開發。
- 檢視被 `cheat_warn` 標記但未處分的名單，看是否有誤判模式需要調整門檻。
